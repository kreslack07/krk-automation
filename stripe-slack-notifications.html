Stripe → Slack: Real-Time Customer Alerts

The single most-requested "I can't believe this is so simple" workflow I build. When a new customer pays you on Stripe, post a message in a Slack channel with their email, plan, and amount. Build time: 5 minutes. Use cases: team awareness, founder dopamine, low-latency support follow-up.

The 2-node n8n workflow

  1. Stripe Webhook — listen for checkout.session.completed
  2. Slack message — post to your #customers channel with the customer email, amount, currency, and product

That's it. No Supabase, no LLM, no transformation. Just event in, message out.

The Slack message format

🎉 New customer!
Name: {{customer_name}}
Email: {{customer_email}}
Plan: {{product_name}}
Amount: {{amount}} {{currency}}
Payment ID: {{payment_id}}

Setup

  1. Create a Stripe webhook (in Stripe dashboard) pointing to your n8n webhook URL, with the checkout.session.completed event
  2. Create a Slack incoming webhook (in Slack API settings) pointing to #customers
  3. Wire them together in n8n with a 2-node workflow

Time: 5 minutes. Cost: A$0.

When this workflow pays for itself

For most founders, the "I have a new customer" notification alone justifies the build. But the real value is downstream: when a customer pays, the workflow can ALSO trigger a personalised welcome email, a Notion CRM row, a fulfilment webhook (for digital products), or a HubSpot deal. The Stripe event becomes the single source of truth for "money came in" across your stack.
